# Repository audit — 16 September 2026

Audited revision: `3983236a24286c6658057c8269504c5d77b34957`.

Scope: Android and web persistence, backup/import, study scheduling, transcript and roleplay flows, speech lifecycle, credential storage, web authentication, service-worker behavior, build configuration, CI, and existing test coverage. This is a source and local-verification audit, not certification of every device, browser, or production deployment. No production services or real AI credentials were exercised.

## Findings

### 1. P1 — A valid saved phrase can make the entire backup impossible to restore

Location: `web/src/lib/db/backup.ts:279`; save path in `web/src/lib/db/repository.ts:60`.

Saving vocabulary does not impose the importer's 200-character German-text limit. Whole transcripts can also be saved as vocabulary. Export accepts these records, but import rejects the whole file before writing anything. A phrase of `"Ich lerne Deutsch. ".repeat(12)` saved successfully and its own exported backup failed with `Vocabulary field exceeds maximum allowed length` in an isolated database probe.

Align save/export/import contracts so every legitimate export can be restored. Include long phrases and collection-size boundaries in round-trip tests; the row-count and file-size caps likewise need an explicit strategy for libraries that outgrow them.

### 2. P1 — A stale study session recreates deleted vocabulary and overwrites newer state

Locations: `web/src/hooks/useStudy.ts:126`, `web/src/lib/db/repository.ts:130`.

The study queue retains complete card snapshots. Submission writes a snapshot using `put`, without rereading or checking the current row inside the transaction. Open Study in tab A, clear progress or delete/edit the card in tab B, then grade in A: the deleted card is recreated, or the edit/newer schedule is overwritten. Two tabs can also reward the same scheduled review independently. The transaction ensures atomic writes but does not validate the snapshot.

A database probe confirmed that clearing progress followed by the exact stale-card update used by Study restores a vocabulary row. Reread inside the transaction, reject missing/stale cards, and update only the appropriate scheduling fields.

### 3. P1 — Typed transcription hides successful results

Locations: `web/src/hooks/useTranscript.ts:211` and `:315`; empty-state condition in `web/src/app/(app)/transcript/page.tsx:96`.

`submitTypedText` runs translation but never sets the displayed source text. The returned `finalText` always comes from the speech recognizer, which remains empty in a browser without speech recognition. Once translation finishes, `isEmpty` becomes true and the page returns to its introductory screen, hiding the translation. Save also reads that empty source text.

An isolated Chromium check disabled speech recognition, entered a fake API key, intercepted Groq with a successful translation, and submitted `Guten Morgen`. The expected translation was absent and the page showed the introductory typed-input form. Keep the submitted text as transcript state shared by typed and spoken input. Test the complete typed translation/save flow, not just the presence of fallback controls.

### 4. P2 — Android roleplay loses turns when recognition ends automatically

Locations: `app/src/main/java/com/aus/deutschflow/ui/viewmodel/RoleplayViewModel.kt:177`; `ui/screens/RoleplayScreen.kt:308`; `service/SpeechRecognizerHelper.kt:429`.

Roleplay waits for `finalText` only after the user calls `stopListeningAndSend`. The recognizer itself sets `isListening=false` when speech ends. If the engine finishes before the user taps Stop, no roleplay collector sends the result. The button now starts a new recording, which clears the previous result. Unlike Transcript and Practice, Roleplay does not consume the helper's completed-utterance stream.

Consume completed utterances exactly once for roleplay, and use Stop only to request finalization. This is a source-confirmed control-flow defect; device reproduction remains outstanding.

### 5. P2 — Clear all progress leaves review history behind on the web

Location: `web/src/lib/db/repository.ts:328`.

The clearing transaction omits `reviewEvents`. A seeded review event survived a successful clear in an isolated database probe. This violates the reset's scope and leaves orphaned learning records. Android already deletes its corresponding table.

Include review events in the same clearing transaction and test every learning-data table.

### 6. P2 — Restoring a backup discards saved transcript analysis

Location: `web/src/lib/db/backup.ts:495`.

Export includes transcript `translation` and `analysisJson`, but import constructs each transcript with only text, timestamp, identity, and modification time. A round-trip probe confirmed both analysis fields become undefined after restoring into a fresh database. Users lose saved translations without an import error. `web/src/hooks/useHistory.ts:40` independently has the same loss on Delete → Undo, because it reinserts only text and timestamp.

Preserve and validate the analysis fields during restore and undo. Add round-trip tests using analyzed transcripts rather than text-only records.

### 7. P2 — Backups omit review history and the current conversation

Location: `web/src/lib/db/backup.ts:35`.

The backup format exports only vocabulary, transcripts, aggregate stats, and activity days. It never exports `reviewEvents` or `roleplayMessages`. Moving to a fresh browser loses the immutable review history and saved conversation. In particular, README explicitly promises review events in the export. An isolated probe verified both collections are absent from the exported object.

Extend the versioned format and import handling, including remapping review-event vocabulary IDs when local IDs change. Preserve compatibility with existing backups.

### 8. P2 — Web translation and word details ignore the selected CEFR level

Location: `web/src/lib/ai/processor.ts:17` and `:21`.

Settings persists a CEFR level, and Groq's translation and interrogation functions accept it. However, the transcript hook and processor pass only text and API key, so the selected level never reaches either prompt. Roleplay and the Android client do forward it.

Read and forward the setting for both translation and word interrogation; verify the outgoing request generated by the user-facing flow.

### 9. P2 — Web roleplay ignores the autoplay setting

Locations: `web/src/hooks/useRoleplay.ts:118` and `:170`.

Both successful opening and continuation responses call `tts.speak` unconditionally. Disabling autoplay in Settings does not silence roleplay. Android checks the preference before speaking.

Check the saved autoplay preference before automatic speech. Keep explicit Speak controls independent of that setting.

### 10. P2 — Both clients record card age as elapsed review time

Locations: `web/src/hooks/useStudy.ts:116`; `app/src/main/java/com/aus/deutschflow/ui/viewmodel/StudyViewModel.kt:144`.

`actualDays` is computed from the vocabulary timestamp, which is creation/latest-save time, rather than the previous review. A card saved 100 days ago and reviewed yesterday records approximately 100 elapsed days when reviewed today. Saving it again changes that metric despite no intervening review. This contaminates the newly introduced review history.

Use a previous-review timestamp or the previous review event and define the first-review case explicitly. Add repeat-review tests on an old card.

- Full Playwright run: **not a clean result**. It encountered Firefox page-creation errors, Chromium worker exits/page-setup timeouts, and WebKit navigation timeouts. The targeted typed-input check reached the application and exposed finding 3.
- Android unit tests and lint: **not completed**. Gradle initially could not establish a loopback connection; a later attempt reported insufficient native JVM memory. No Android pass is claimed, and instrumentation/device validation was not performed.
- Authentication, key storage, manifests, migrations, AI request boundaries, and service-worker code were reviewed. No additional confirmed critical security exploit was established. Live speech engines, offline upgrades between deployed builds, and production-host configuration remain unverified.

## Coverage priorities

The existing suite passes despite these findings because several tests stop at helpers or initial UI state. Add end-to-end typed translation/save coverage, complete backup/reset table contracts, multi-tab study conflicts, analyzed transcript round trips, CEFR/autoplay integration checks, and Android automatic speech completion. Some service-worker tests assert source strings or duplicate the intended algorithm rather than execute worker lifecycle behavior; actual install/upgrade/offline tests are needed for that boundary.

The initial audit above made no application-code changes. The following remediation was subsequently authorized and implemented.

## Remediation follow-up

All ten findings have code fixes and regression coverage in the working tree:

- Backup v2 preserves transcript analysis, review events (with remapped card IDs), and saved roleplay. Version 1 remains supported. Validation uses the whole-file 10 MB budget instead of rejecting legitimate long phrases or large row counts. Exports validate before offering a download; oversized data remains on the device. Existing local conversations are preserved rather than combined with imported scenarios.
- Study reviews now validate and commit against the current IndexedDB row in one transaction, preventing deleted-card resurrection, stale overwrites, and duplicate rewards across tabs.
- Typed translation owns its displayed source text, remains available for subsequent submissions, and passes the selected CEFR level through translation and word details.
- Android roleplay subscribes to completed utterances, including automatic completion; manual Stop no longer resends retained text. Web roleplay honors autoplay for opening and continuation responses.
- Reset clears review events; History undo restores complete transcript metadata and stable identity.
- Both clients compute elapsed review days from the previous review event (zero for a first review), not card creation or editing.

Verification after remediation:

- Web: **298 tests passed across 26 files**, ESLint and TypeScript passed, and production build passed.
- Android: **118 unit tests passed across 13 suites**. Application code and instrumentation-test Kotlin compilation passed. Device tests have not been executed.
- Repository static checks passed: 224 English/German keys on each client, palette, contrast, and clutter checks.
- Android lint remains incomplete: the reduced-memory run failed during analysis with JVM Metaspace exhaustion. No lint pass is claimed.
- Both focused Chromium regressions passed: typed translation/display/save/A1 word details and roleplay autoplay off/on. The runner then reported a server-teardown timeout, so the overall command exited with an infrastructure error. No full browser-suite pass is claimed.

Gradle verification required a per-process Unix-domain-socket temporary-directory override to bypass the local loopback error and reduced-memory test settings. These are verification-only workarounds, not permanent project configuration changes. No commit or deployment was made.
