## Findings

### R-01 · P2 · The "cards due" banner doesn't update after a review [Static]
`DashboardContent` gets `dueCount={study.dueCount}` (`study/page.tsx:59`). `useStudy` sets `dueCount` only in `startSession` (`useStudy.ts:71`), from the snapshot taken when the session loads. Rating cards doesn't change it. A user with 5 due cards who reviews all 5 and goes back to the Dashboard tab still sees "5 cards due for review" and a *Start Daily Review* button, which opens a finished session.
**Fix:** derive the count from the live queue (remaining due cards in `studyList`), or recompute it when a card is rated. Add a test.

### R-02 · P2 · Hardcoded English in the new UI [Static]
The redesign added user-visible strings that bypass `i18n.ts`, so German users see English. `audit_repo.py` can't catch this, because it compares only keys in the resource files (the same gap as X-02 in the last audit).
- `DashboardContent.tsx:59`: "Ready to practice speaking or explore vocabulary."
- `DashboardContent.tsx:74`: "SRS Spaced Repetition"
- `DashboardContent.tsx:80`: "Strengthen your German memory retention with targeted review."
- `GlassTextField.tsx:70`, `:82`: `aria-label="Clear search"` and the `"Search"` fallback. Screen readers announce these in English. `action.clearFilter` already exists for the first one.
- `transcript/page.tsx:481`: the placeholder "z.B. Wie geht es dir heute?" is German on the English UI too. A German example sentence may be intended. If so, it still belongs in `i18n.ts`, so the EN text can say "e.g.".
- `WordDetailsSheet.tsx:138` wraps the example in English quotes (`"…"`) inside `lang="de"`. German uses „…“.

**Fix:** move them into `i18n.ts` (EN and DE). Consider extending `audit_repo.py` to flag JSX text nodes and string `aria-label`s.

### R-03 · P3 · Switching to *Type* while recording hides the stop button [Static]
In the active transcript view, the mode switch (`transcript/page.tsx:296–321`) stays enabled while `state.isListening`. Choosing *Type* swaps `OracleMic` (the only stop control) for `TypedInput`, and recognition keeps running. The user has to switch back to stop it. Switching modes doesn't call `stopListening()`.
**Fix:** disable the switch while listening, or stop listening when the mode changes to *Type*.

### R-04 · P3 · The mode switch isn't exposed as a toggle [Static]
The comment calls it an "Accessible Mode Switcher" (`transcript/page.tsx:139`), but the two buttons show their selected state only through colour. They have no `aria-pressed` (or `role="radiogroup"`/`radio` with `aria-checked`). The *Speak* option is labelled `transcript.startRecording` ("Start recording"), which reads as an action, not a mode. The same markup is copied twice (lines 141–166 and 296–321).
**Fix:** one shared `InputModeSwitch` with `aria-pressed` and its own "Speak" label.

### R-05 · P3 · Two "Start Daily Review" buttons, one shown when nothing is due [Static]
`DashboardContent` passes `onStartReview` to both `DueTodayBanner` and `DailyGoalCard` (lines 94 and 189). With cards due, the screen has two identical CTAs. With none due, the banner says "All caught up!" while the goal card still offers *Start Daily Review*, which opens extra practice under a misleading label.
**Fix:** keep the banner's button only, or hide the goal card's button when `dueCount === 0`.

### R-06 · P3 · "1 cards due for review" [Static]
`dashboard.dueTodayBanner` is `"{0} cards due for review"` / `"{0} Karten heute fällig"`, with no singular. `i18n.ts` already pairs `streak.day` / `streak.days` for exactly this case.
**Fix:** add a singular key and choose it by count.

### R-07 · P4 · Hygiene
- **Docs claim more than the code does.**
  - `AudioWaveform.tsx:14–15` says the meter "respects prefers-reduced-motion". Nothing in the file reads it.
  - `useViewport.ts:30–32` says `useSyncExternalStore` "eliminates layout shifts (CLS) and extra render cycles". `getServerSnapshot` returns `false`, so hydration still renders `false` and then corrects it, as the old `useEffect` did. The behaviour is the same, but the claim is wrong. Also, `subscribe` is a new closure on every render, so React re-subscribes to `matchMedia` on every render. Hoisting it, or memoising per query, avoids that.
  - The same sentence also turned "library's" into "librarys" (line 16).
- **"Why" comments were deleted without replacement.** These deletions remove context that the code doesn't carry:
  - `WordDetailsSheet.tsx:31`: why the sheet is split, which is a hook-order constraint.
  - `WordDetailsSheet.tsx:829`: when the dictionary-form notice appears.
  - `DashboardContent.tsx`: why `text-tertiary` and the azure gradient are used instead of Tailwind green / `#00E5FF` (a 1.7:1 contrast issue).
  - `transcript/page.tsx`: why typing replaces the mic in Firefox.
  - `AudioWaveform.tsx`: the idle-comb note.
- `icons.tsx:367`: the orphaned `/** Material sync … */` doc comment now sits on `CloseIcon`, so editor hovers describe the wrong icon.
- `transcript/page.tsx:69–70`: a stray double blank line.
- **Flashcard back face** (`study/page.tsx:363–370`): the article is shown twice, as text ("der Hund") and as the `ArticleBadge` just below it.
- **Search:**
  - `foldGerman` is applied to the text, so "Mädchen" matches "maedchen". It doesn't help the case most users type, "madchen" for "Mädchen".
  - History search now runs `foldGerman` over every transcript's full text on each keystroke, without the `useDeferredValue` that vocabulary search uses. That is fine at the current sizes, but worth deferring like the library.
