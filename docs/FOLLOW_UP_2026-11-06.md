## Optimized startup measurement build

The benchmark build type inherits release minification/resource shrinking,
remains non-debuggable, adds shell profiling, and uses local debug signing.
Its application ID is com.aus.deutschflow.benchmark so it can coexist with the
user's installed app. Production release signing and manifest are unchanged.
No production signing credentials exist in this checkout.

Build with `gradlew.bat assembleBenchmark`. The timing tool now accepts --package
and --build-label; use the benchmark application ID and identify the exact local
build. It launches the namespace's MainActivity explicitly. This is a repeatable
ActivityManager process-cold timing experiment, not a Macrobenchmark suite,
controlled compilation experiment, time-to-full-display, or production percentile.
No app-specific profile or startup scheduling change is justified solely by these
timings. Macrobenchmark/Perfetto remains the next tool for causal optimization.
